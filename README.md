# سدرة — كاشير موبايل تجريبي V2

## الجديد في النسخة
- نفس البيع السريع، كاش وآجل، مع حفظ العمليات محليًا في IndexedDB.
- زر **باركود** يستخدم كاميرا الموبايل عند توفر `BarcodeDetector` في المتصفح. يدعم EAN/UPC وعددًا من الأنواع الأخرى. **لا يحتاج إنترنت للقراءة بعد تثبيت التطبيق**، لكن قد لا يدعمه كل هاتف/متصفح. إن لم يدعمه هاتفك، يُعرض حقل لإدخال الباركود يدويًا. لا نفترض أن كل منتج عنده باركود مسجل؛ أول مسح لرمز مجهول يسمح بربطه بصنف موجود أو إضافة صنف جديد.
- شعار «سدرة» الحقيقي المستخرج من ملف SVG المرفق كأيقونة PWA؛ بدون العناصر الأخرى الموجودة في ملف الرسم الأصلي.
- اختيار عميل آجل من قائمة قابلة للبحث أو إنشاء عميل جديد داخل نفس الفاتورة.
- صفحة «الآجل»: أسماء العملاء، الأرصدة، الفواتير المفتوحة، **كل التاريخ**، تفاصيل أي فاتورة، سداد جزئي أو كامل.
- سداد الفاتورة ينشئ عملية تحصيل كاش وحركة تخفيض للآجل؛ **لا يمسح الفاتورة** ولا يقلل مبيعات يوم صدورها. بعد السداد تختفي من «الفواتير المفتوحة» وتبقى في «كل التاريخ» للمراجعة.
- سجل تحصيلات مستقل وحساب نهاية اليوم.

## النشر: تطبيق جديد مستقل عن القديم
1. على GitHub (حساب adham253)، أنشئ مستودعًا جديدًا باسم `cashier-v2` واجعله **Public**. لا ترفع على مستودع `cashier` القديم إن كنت تريد إبقاء النسختين منفصلتين.
2. فك ضغط ملف ZIP. ارفع **كل الملفات الموجودة داخل الفولدر مباشرة إلى جذر المستودع**، بحيث يظهر `index.html` في الصفحة الأساسية بجوار `sw.js`.
3. افتح Settings → Pages → Deploy from a branch → main → /(root) → Save.
4. العنوان المتوقع **بعد نجاح النشر** هو: `https://adham253.github.io/cashier-v2/` (لا يعني ذكر الرابط هنا أنه نُشر بالفعل).
5. افتح الرابط مرة واحدة من Chrome على Android، ثم ⋮ → Add to Home Screen / Install app.
6. انتظر التحميل الأول، ثم جرّب فتحه بوضع الطيران. بالنسبة للكاميرا أعطِ الإذن عند طلبه، وتأكد أن المتصفح يدعم كشف الباركود.

## التجربة قبل البيع الحقيقي
1. أضف صنفًا إلى فاتورة كاش وأغلق التطبيق وافتحه. تأكد أن الفاتورة محفوظة.
2. اعمل فاتورة آجل باسم عميل جديد؛ افتح «الآجل» وابحث عنه وتأكد من رصيد الفاتورة.
3. سدّد جزءًا من الفاتورة وتأكد من نزول الرصيد؛ ثم سدّد الباقي وتأكد أن الفاتورة ظهرت في «كل التاريخ» ولم تعد في «المفتوحة».
4. نزّل نسخة احتياطية JSON من «المزيد». افحص محتوياتها واحفظها في مكان مختلف.
5. جرّب إغلاق اليوم وتصدير Excel، ولا تدخل بيانات حقيقية قبل التأكد من النتائج.

## هام عن البيانات
- هذا **تطبيق منفصل تجريبي**؛ قاعدة بياناته اسمها `SedraPOS_Trial_v2` مختلفة عن قاعدة النسخة الأولى. لا يتم نقل الفواتير السابقة تلقائيًا. لو تحتاج نقل بيانات من التطبيق القديم، أولًا صدّر Backup منه؛ ويمكن استعادته يدويًا في النسخة التجريبية، **مع استبدال كل بياناتها الحالية**. أنصح بنسخ احتياطي للنسختين أولًا.
- المعلومات تحفظ محليًا في متصفح نفس الموبايل، لا في GitHub ولا على السحابة تلقائيًا. حذف بيانات الموقع، استخدام وضع التصفح الخفي، أو تلف/ضياع الهاتف قد يفقد البيانات. نزل Backup إلى مكان منفصل بصورة منتظمة.
- الاستضافة على GitHub Pages **عامة للملفات البرمجية والأصناف الأولية**، وليست حسابًا محميًا. **لا ترفع أي بيانات عملاء أو Backup JSON على GitHub**.
- الكاشير على هاتفين منفصلين دون مزامنة سيكون لهما سجلان مختلفان؛ النسخة لا توفر قاعدة مشتركة لحظية أو توافقًا بين أجهزة متعددة.
- إذا كان المتصفح لا يدعم `BarcodeDetector` فلا يمكن ضمان المسح بالكاميرا في هذه النسخة؛ متاح إدخال الكود يدويًا.
- أسعار الأصناف من النسخة السابقة؛ **أرصدة المخزون الحالية غير مؤكدة** حتى تثبيتها بجرد فعلي.
- صلاحية PIN هي حاجز واجهة لا تشفير قوي لقاعدة البيانات ضد من يتحكم بالجهاز.
